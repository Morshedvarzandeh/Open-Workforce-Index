Help when you need it
What do the model and price mean?

A worker is a model with a particular role and tools. The displayed USD amount estimates the cost of a usable result, including possible retries. It is not a bill or a guaranteed price. A recommendation does not charge you; running a connected model may use your provider's paid usage or subscription allowance.

OWI starts with assumed abilities and improves its estimates using feedback. A quality option has a stronger estimated confidence bound; it is not a guarantee that its answer will be correct.

How do I check a result?

Review it against what you asked for. The optional requirements box accepts plain language. For automatic checks, use one per line: contains:Friday, min-words:60, or json. Browser mode can check those against a pasted answer. Subjective requirements need your review, or an available separate checker in connected mode.

For a task split into parts, review each part separately. The shared checklist applies to single-part tasks; connected mode creates a checklist for each part. Later parts do not automatically receive earlier results: include the needed context yourself.

How do I connect a model?

On your computer, install the project's prerequisites: Git, Python 3, and Rust 1.87 or newer. Open a terminal in this repository and run:

tools/owi-serve

Open the address it prints. First launch builds the engine and may take a few minutes. Configure a supported model CLI on that computer, then follow the connection instructions. Custom commands go in .owi-quick/runners.json by default. A configured command must also have working provider access.

Keep provider credentials in your CLI's credential store. The task box is for the work you want done.

Why is there no suitable model?

The current roster may lack the task's tools, privacy clearance, or sufficient quality evidence. Try a more specific task, connect a suitable worker, or add verified evidence. Increasing your budget does not remove these requirements.

For confidential work, the worker must be explicitly cleared for it. This filter does not configure a private model for you.

Where does my feedback go?

Choose “worked” after reviewing a result. If it did not work, distinguish a poor model answer from an unclear request or a setup problem; only a model-caused failure should reduce that model's estimate.
